# 똥손카메라 — 촬영 모드 기획서 (인물 / 자연 / 사물)

- **작성일**: 2026-07-05
- **문서 유형**: 개발 기획서 (구현용)
- **상태**: 설계 확정, 구현 계획 수립 전
- **선행**: Phase 1(온디바이스 가이드), Phase 2(클라우드 구도 추천), 시각 구도 가이드(targetBox) 완료.
  이 문서는 기존 단일(인물) 경험을 **3개 촬영 모드**로 확장한다.

---

## 1. 개요

### 1.1 한 줄 정의
사용자가 **인물 / 자연 / 사물** 중 하나를 골라 촬영하면, 그 모드에 맞게
**온디바이스 실시간 가이드**와 **클라우드 ✨ 구도 추천**이 함께 바뀌는 기능.

### 1.2 문제 정의
지금 앱은 **인물 촬영 하나만** 가정한다. 풍경이나 물건을 찍을 때는 얼굴 감지 기반
가이드(헤드룸·눈높이 등)가 무의미하거나 방해가 된다. 대상 유형에 맞는 가이드가 필요하다.

### 1.3 핵심 가치
> 무엇을 찍는지 한 번 고르면, 실시간 가이드도 AI 추천도 그 대상에 맞춰진다.

---

## 2. 모드 정의 (핵심 계약)

모드는 3가지. 앱·백엔드 공통 문자열 상수로 표현한다.

| 모드 | 문자열 | 온디바이스 실시간 가이드 | 클라우드 ✨ 추천 |
|---|---|---|---|
| **인물** | `person` | 현재 그대로 — 얼굴 감지 → 헤드룸·크롭·3분할·줌·눈높이각 + 시각 `targetBox` | 인물 구도 프롬프트, `targetBox` 포함 |
| **사물** | `object` | ML Kit **사물 감지** → 가장 큰 사물 박스 기준 중앙/3분할/줌 + 시각 `targetBox` 재사용 | 사물 구도 프롬프트, `targetBox` 포함 |
| **자연** | `nature` | 수평(level) + 격자만 (인물·사물 감지 없음) | 풍경 프롬프트, **텍스트만**(`targetBox` 없음) |

- 세 모드 모두 **수평계·격자**는 공통으로 동작(대상과 무관한 기본 보조).
- 기본 모드는 **인물**. 마지막 선택 모드는 재실행 시 유지.

## 3. 모드 선택 UI (하단 슬라이더/휠)

```
┌─────────────────────────────┐
│        (카메라 프리뷰)        │
│      + 모드별 실시간 가이드    │
│                             │
│      ‹  인물 · [자연] · 사물 ›  │ ← 하단 모드 휠(중앙=현재 모드)
│      ⊞        ◯        ✨      │ ← 격자 · 촬영 · 구도추천
└─────────────────────────────┘
```

- 촬영 버튼 **바로 위**에 가로 모드 선택기. 일반 카메라앱의 촬영 모드 휠 관례를 따른다.
- **좌우 스와이프 또는 라벨 탭**으로 전환. 중앙(강조)이 현재 모드.
- 전환 즉시: (a) 온디바이스 감지기·가이드 교체, (b) 진행 중이던 시각 가이드(targetBox)·카드 초기화(모드가 바뀌면 이전 추천은 무효).
- 선택값은 `SharedPreferences`에 저장(`shooting_mode`), 앱 재실행 시 복원. 없으면 `person`.
- 렌더러(휠 위젯)에는 판단 로직을 넣지 않는다 — 현재 모드 표시와 탭/스와이프 콜백만.

## 4. 데이터 계약 변경 (구조화 출력)

### 4.1 `mode` 요청 필드 추가
클라우드 요청 페이로드에 `mode` 문자열(`"person"`/`"nature"`/`"object"`)을 추가한다.
백엔드는 이 값으로 **모드별 프롬프트**를 선택한다.

### 4.2 `targetBox`를 선택(optional)으로 완화
자연 모드는 배치할 단일 피사체가 없어 `targetBox` 없이 **텍스트 조언만** 반환한다.
따라서 계약에서 `targetBox`를 **필수 → 선택**으로 바꾼다.

- **앱** `CompositionAdvice.targetBox`는 이미 `TargetBox?`(nullable)이며 누락 시 `null`로 방어 파싱 중 — **변경 없음**.
- **백엔드** `COMPOSITION_SCHEMA`에서 `targetBox`를 `required`에서 제거(속성 정의는 유지).
- **백엔드** `parseAdvice`: `targetBox`가 있으면 검증해 담고, 없으면 `undefined`로 둔다(누락은 더 이상 에러 아님). 값이 있는데 형식이 틀리면 종전처럼 에러.
- `CompositionAdvice.targetBox`(백엔드 타입)를 `TargetBox | undefined`로 완화.

### 4.3 모드별 프롬프트 (백엔드)
`SYSTEM_PROMPT`/`buildUserText`를 모드 인자를 받도록 바꾼다.

- **person**: 현재 프롬프트 유지 — "인물을 놓을 더 좋은 목표 위치를 `targetBox`로".
- **object**: "사진 속 **주요 사물**을 놓을 더 좋은 목표 위치를 `targetBox`로. 3분할·여백·크기를 고려." (targetBox 포함)
- **nature**: "**풍경/자연** 사진의 구도 조언을 한국어로. 수평선 위치·3분할·전경/원경 균형 위주. 배치할 단일 피사체 박스는 만들지 말고 **`targetBox`는 생략**." (headline+rationale만)

온디바이스 지표(tilt, hasPerson, personCenter)는 인물 모드에서만 의미 있으므로, 모드에 맞는
참고 문구만 덧붙인다(자연·사물에서는 인물 중심 좌표 문구 생략).

## 5. 온디바이스: 사물 감지 (신규)

### 5.1 의존성
- **`google_mlkit_object_detection`** 추가. 기존 `google_mlkit_face_detection`과 동일한 ML Kit 패턴.

### 5.2 감지기 인터페이스
- 기존 `PersonDetector`와 병렬로, **모드에 따라 감지기를 교체**한다.
- 사물 모드: ML Kit Object Detection이 반환한 박스 중 **면적이 가장 큰 하나**를 정규화 `PersonBox`로 변환해 반환(기존 값 객체 재사용 — 좌표 규약 동일).
- 라벨/분류는 이번 범위 밖. 박스만 사용.

### 5.3 가이드 계산 (순수 함수, 재사용)
사물 박스는 인물 박스와 **같은 정규화 `PersonBox`** 이므로 기존 순수 함수를 재사용한다.
- 중앙/3분할: 기존 `computeThirds(centerX, centerY)`.
- 줌(크기 적정): 기존 `computeZoom(height)`.
- 헤드룸·크롭·눈높이각은 인물 전용 → **사물 모드에서는 계산하지 않는다**.
- 이를 위해 `AnalysisEngine.buildMetrics`에 `mode`를 전달해 모드별로 채우는 지표를 분기한다(순수 로직, TDD 대상).

### 5.4 자연 모드
감지 없음. `AnalysisEngine`는 tilt/angle만 담은 `GuideMetrics` 반환(현재 `person==null` 경로와 동일). 오버레이는 격자·수평계만.

### 6.2 백엔드 (재배포 필요)
| 파일 | 변경 |
|---|---|
| `functions/src/schema.ts` | `targetBox`를 `required`에서 제거. 모드별 프롬프트 빌더(`SYSTEM_PROMPT`/`buildUserText`가 mode 인자) |
| `functions/src/advice.ts` | `mode` 입력 파싱·검증(3값 화이트리스트, 기본 person). `targetBox` optional 파싱. `CompositionAdvice.targetBox?` |
| `functions/src/claude.ts` | `requestAdvice`에 mode 전달 → 모드별 프롬프트 사용 |
| `functions/test/*` | mode별 프롬프트·targetBox optional 파싱 케이스 |

### 6.3 데이터 흐름
1. 사용자가 하단 휠로 모드 선택 → `camera_screen` 상태 갱신 + `mode_store` 저장 + 시각 가이드 초기화.
2. 매 프레임: 모드에 맞는 감지기(인물/사물/없음) → `AnalysisEngine.buildMetrics(mode)` → 모드별 오버레이.
3. ✨ 추천: `CloudAdvisor.suggest(..., mode)` → 백엔드가 모드별 프롬프트로 호출 → `targetBox`는 인물·사물에만.
4. 결과 렌더: 인물·사물은 시각 targetBox 가이드+미니맵+카드, 자연은 카드(텍스트)만.

## 7. 비기능 요구사항

- **성능**: 감지기는 모드당 하나만 활성(동시 실행 안 함). 순수 지표 계산은 프레임당 O(1).
- **견고성**: 감지 실패(사물/인물 미검출) 시 해당 박스 가이드 생략, 격자·수평계는 유지. mode 미지정/이상값이면 백엔드·앱 모두 `person`으로 폴백.
- **일관성**: 좌표 정규화 0~1·원점 좌상단, 색 규약(녹=좋음/빨=주의), 정렬 판정 문자열 `'좋아요'` — 기존과 동일.
- **네트워크**: 여전히 추천 요청 시 1회. 모드 전환·온디바이스 가이드는 네트워크 0회.

## 8. 범위 밖 (Out of Scope)

- 사물 **분류/라벨**(무슨 물건인지)에 따른 맞춤 조언 — 이번엔 박스만.
- 다중 사물/다중 인물 각각의 목표 배치.
- 자연 모드의 수평선 자동 검출(하늘/땅 경계) — 격자·수평계로 대체.
- 모드별 촬영 파라미터(노출·초점 모드) 제어 — 구도 가이드에 한정.
- 모드 전환 애니메이션/사운드 등 부가 연출.

## 9. 리스크 및 대응

| 리스크 | 대응 |
|---|---|
| ML Kit Object Detection가 여러 박스 반환/불안정 | 최대 면적 하나만 채택, 미검출 시 박스 가이드 생략(격자·수평 유지) |
| `targetBox` optional 완화가 기존 인물 흐름 파손 | 앱은 이미 nullable — 백엔드만 변경, 인물·사물 경로는 targetBox 계속 반환. 테스트로 회귀 방지 |
| 새 의존성으로 안드로이드 빌드 체인 재파손(minSdk/compileSdk) | face_detection과 동일 계열이라 위험 낮음. 추가 후 즉시 실기기 빌드 확인 |
| 모드 전환 시 이전 추천이 새 장면에 남음 | 전환 시 `_advice`/시각 가이드 즉시 초기화 |

## 10. 성공 지표

- 각 모드에서 대상에 맞는 실시간 가이드가 뜬다(인물=헤드룸 등, 사물=중앙/줌, 자연=수평·격자).
- ✨ 추천이 모드별로 다른 조언을 준다(자연은 텍스트만, 인물·사물은 시각 박스).
- 모드 선택이 재실행 후에도 유지된다.

## 11. 완료 정의

하단 휠로 인물/자연/사물 전환이 되고, 모드별 온디바이스 가이드와 ✨ 추천이 각각 동작한다.
순수 로직(모드 분기·사물 지표) + 백엔드 스키마/파서 테스트 통과, `tool/verify.sh` 통과,
백엔드 재배포 후 실기기에서 세 모드 모두 확인.
