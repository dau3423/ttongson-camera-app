# 촬영 직후 AI 무드 보정 — 설계 (spec)

- 작성일: 2026-07-18
- 상태: 설계 합의 완료 (구현 계획 작성 전)
- 관련: 기존 AI 구도 추천(`lib/cloud/`, `functions/src/advise.ts`) 인프라 재사용

## 1. 목적 / 한 줄 정의

촬영 직후 결과 화면에서 이용자가 "오늘의 무드"를 선택하면, AI가 그 사진에 맞는
보정값을 산출해 기기에서 적용하는 **터치 한 번 AI 무드 보정** 기능.

- 스토어 마케팅 문구("무드를 선택하면 AI가 사진 분위기를 찰떡같이 바꿔줌")를 **실제 기능**으로 뒷받침한다.
- 밝기·대비·채도·색온도 등 **파라미터 기반 보정**이며, 생성형 재그리기(image-to-image)가 아니다.

## 2. 사용자 흐름

```
촬영(셔터)
  → 원본을 지금처럼 즉시 갤러리 저장 (유실 방지)
  → [촬영 결과 화면] (신규)
      · 방금 찍은 사진 크게 표시
      · 하단 '오늘의 무드' 칩 스트립: 원본 · 따뜻 · 시원 · 필름 · 무디 · 쨍 · 흑백
      · 무드 탭 → (프리셋 즉시 미리보기) → (AI 값 도착 시 갱신)
      · [저장] 선택한 보정본을 갤러리에 추가 저장 (원본은 이미 저장됨 → 결과적으로 둘 다)
      · [공유] 커뮤니티 업로드 흐름으로 연결 (기존 마스크 편집 → 캡션)
```

- 무드를 고르지 않으면 원본만 남는다.
- 무드를 골라 저장하면 **원본 + 보정본** 둘 다 갤러리에 존재한다.

## 3. 무드 세트 (MVP, 6종)

| 키 | 라벨 | 방향 |
|---|---|---|
| `warm` | 따뜻하게 | 색온도↑(앰버), 부드러운 톤 |
| `cool` | 시원하게 | 색온도↓(블루), 차분 |
| `film` | 필름/빈티지 | 약한 대비·바랜 느낌·미세 틴트 |
| `moody` | 무디 | 채도↓, 매트·침착 |
| `vivid` | 쨍하게 | 채도↑·대비↑, 화사 |
| `bw` | 흑백 | `grayscale=true`, 대비 유지 |

각 무드는 **온디바이스 기본 프리셋값**을 가진다(오프라인·AI 실패 시 사용).

## 4. AI 동작 (기존 `advise` 패턴 재사용)

- 클라이언트가 다운사이즈 JPEG + 선택 무드를 서버 콜러블 `enhance`로 전송.
- 서버(`functions/src/enhance.ts`)가 Claude(비전 + json_schema 구조화 출력)로
  **보정 파라미터**를 반환한다:

```jsonc
// MoodParams — 모든 값 -1.0 ~ 1.0 로 클램프, grayscale만 bool
{
  "brightness": 0.0,
  "contrast": 0.0,
  "saturation": 0.0,
  "temperature": 0.0,   // 음수=쿨(블루), 양수=웜(앰버)
  "tint": 0.0,          // 음수=그린, 양수=마젠타
  "grayscale": false
}
```

- 서버 프롬프트: "이 사진에 <무드>를 자연스럽게 입히되 과하지 않게, 위 범위 내 값만 반환."
- 앱은 이 값으로 **원본 해상도 이미지를 기기에서 보정**(서버는 값만 전달, 픽셀은 로컬 처리 →
  화질·용량·프라이버시 안전).
- **App Check 강제 · 레이트리밋 · consent 게이트**는 기존 AI 추천과 동일하게 재사용.

## 5. 핵심 폴리시: 프리셋 즉시 미리보기 + AI 갱신 + 캐시

1. 무드 탭 즉시 → 해당 무드의 **내장 프리셋값**으로 보정해 바로 미리보기(지연 0).
2. 동시에 `enhance` 호출 → **AI 값 도착 시** 그 값으로 다시 보정해 미리보기 갱신.
3. `(사진 식별, 무드)` 단위로 AI 결과를 **캐시** → 같은 무드 재탭 시 재호출하지 않음.
4. AI 호출 실패·타임아웃·오프라인·consent 미동의 → 프리셋 결과를 그대로 유지(조용히 폴백).

→ 즉각 반응성 + "AI가 사진별로 맞춤" + 비용/발열 억제를 모두 만족.

## 6. 구조 (계산=순수 TDD, 렌더/IO/플러그인=분리)

| 파일 | 책임 | 검증 |
|---|---|---|
| `lib/analysis/mood_adjust.dart` | **순수 Dart** — `MoodParams` 값객체 + `adjustPixel(r,g,b,params)` 픽셀 수학(플러그인/image 미사용) | 엄격 TDD |
| `lib/edit/mood.dart` | 무드 6종 enum·라벨·기본 프리셋값 | 순수, 단위테스트 |
| `lib/edit/mood_processor.dart` | `image` 패키지로 디코드→픽셀 매핑(`adjustPixel`)→인코드, EXIF 제거 | 기기 수동 검증 |
| `lib/cloud/mood_advisor.dart` | 이미지+무드 전송, `enhance` 호출·파싱, 캐시 | 기기 수동 검증 |
| `lib/screens/capture_result_screen.dart` | 결과 화면 조립(무드 칩·미리보기·저장/공유) | 기기 수동 검증 |
| `functions/src/enhance.ts` (+`schema.ts` 확장) | Claude 보정값 구조화 출력, App Check·레이트리밋 | 서버(vitest) |

- 기존 `lib/cloud/advice_image.dart`(다운사이즈·base64), `device_id.dart`, `advice_consent.dart` 재사용.
- `camera_screen.dart` 셔터 핸들러 → 촬영 결과 화면 push 로 연결.

## 7. 데이터 흐름

```
[셔터] takePicture → 원본 JPEG (즉시 갤러리 저장)
   → CaptureResultScreen(원본 경로)
        무드 탭:
          (1) mood.dart 프리셋 → mood_processor(원본) → 미리보기
          (2) mood_advisor(다운사이즈 원본, 무드) → enhance(서버) → MoodParams
               → mood_processor(원본, MoodParams) → 미리보기 갱신 + 캐시[무드]=params
        저장: mood_processor(원본, 최종 params) → gallery_saver_plus 저장
        공유: 보정본 파일을 커뮤니티 업로드(마스크 편집 → 캡션)로 전달
```

## 8. 에러 처리

- AI 실패/타임아웃/오프라인 → 프리셋 결과 유지(사용자에겐 별도 에러 표시 없음, 결과는 나옴).
- consent 미동의 → AI 미호출, 프리셋만 사용.
- 저장/공유 실패 → 스낵바로 알림.
- 이미지 디코드 실패(HEIC 등) → 원본 그대로 저장하고 보정 스킵 + 안내.

## 9. 테스트 전략

- `mood_adjust.dart`(순수): 각 파라미터의 **항등(0=변화 없음)·경계·클램핑**, grayscale 변환,
  색온도 방향(양수=웜) 등을 단위테스트로 검증. TDD로 구현.
- `mood.dart`: 각 무드 프리셋이 유효 범위 내인지 단위테스트.
- `mood_processor`·`mood_advisor`·화면·서버: 기기/수동 검증(단위테스트 무의미한 영역).
- 서버 `enhance.ts`: 파서/스키마 검증은 vitest(기존 advice 테스트 패턴).

## 10. 스토어 영향

- 이 기능 출시 후에만 스토어 설명에 "AI 무드 보정"을 기재한다(허위광고 방지).
- 개인정보 처리방침에 이미 "AI 추천을 위해 이미지를 Anthropic에 전송"이 기재됨 →
  무드 보정도 동일 범주라 방침 추가 수정 불필요(문구 재확인만).

## 11. 범위 밖 (YAGNI / 후속)

- 갤러리 기존 사진 보정, 커뮤니티 업로드 단계 보정(이번엔 촬영 직후만).
- 무드 강도 슬라이더, 커스텀 필터 저장.
- 생성형 이미지 편집(재그리기).
- 흑백 외 추가 무드 확장.
