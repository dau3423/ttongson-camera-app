# 리모컨 촬영 (2대 연결) 설계

날짜: 2026-08-04
상태: 승인됨

## 1. 개요

휴대폰 2대를 같은 Wi-Fi/핫스팟으로 연결해, 한 대는 **촬영 기기(호스트)**, 다른 한 대는 **리모컨**으로 쓰는 기능. 삼각대·거치 셀프 촬영에서 구도를 리모컨으로 확인하며 찍는다.

### 요구사항 (확정)

- 리모컨 화면: **실시간 프리뷰** + 셔터
- 리모컨 제어: 셔터, 타이머(3/5/10초), 줌, 전/후면 전환, 촬영 모드·구도 가이드 상태 확인
- 연결: **같은 Wi-Fi 또는 핫스팟** (인터넷 불필요, 서버 비용 0)
- 플랫폼: **iOS↔Android 혼용 지원**
- 사진은 기존 플로우대로 **촬영 폰 갤러리에만 저장**

### 선택한 접근: 로컬 WebSocket + JPEG 프레임 스트림

촬영 폰이 앱 내 WebSocket 서버(`dart:io`)를 열고, 리모컨이 QR(ip·port·일회용 토큰)을 스캔해 접속한다. 프리뷰는 ML 분석용으로 이미 받고 있는 카메라 프레임을 재사용해 ~480p JPEG 10~15fps로 전송한다.

기각한 대안:
- **WebRTC**: 화질·지연 최고지만 기존 `camera` 플러그인 파이프라인과 카메라 소유권 충돌, 시그널링 채널이 따로 필요. 과한 스펙.
- **HTTP 스냅샷 폴링**: 실시간 프리뷰 요구 미충족.

## 2. 모듈 구조

```
lib/remote/
  protocol/                       # 순수 Dart — plugin/dart:io import 금지, TDD 대상
    remote_message.dart           # 메시지 모델 + JSON 직렬화/파싱
    pairing_payload.dart          # QR 페이로드(ip, port, token) 인코딩/디코딩
    remote_session.dart           # 세션 상태 머신 + 배압 정책
  transport/                      # dart:io 의존
    remote_server.dart            # 호스트: WebSocket 서버, 토큰 검증, 클라이언트 1대 제한
    remote_client.dart            # 리모컨: 접속·자동 재접속
  host_controller.dart            # 촬영 화면 ↔ 서버: 프레임 축소 전송, 명령 실행
screens/
  remote_pairing_screen.dart      # 역할 선택 + QR 표시/스캔
  remote_control_screen.dart      # 리모컨 화면
```

새 의존성: `qr_flutter`(QR 생성), `mobile_scanner`(QR 스캔). 통신은 `dart:io`만 사용.

플랫폼 설정: iOS `Info.plist`에 `NSLocalNetworkUsageDescription` 추가. Android는 같은 네트워크 소켓 통신에 추가 권한 불필요(INTERNET 권한은 기존 보유).

## 3. 데이터 흐름

1. 촬영 폰: 카메라 화면 상단 메뉴 "리모컨 촬영" → 역할 선택 → 서버 시작 → QR 표시
2. 리모컨 폰: QR 스캔 → 접속 → `hello`(토큰) → `welcome`(화면비·줌 범위·현재 상태)
3. 호스트: 프레임 축소 JPEG 전송(기존 `advice_image.dart`의 축소 인코딩 재활용) + `state`(가이드 요약·줌·전후면·모드, 변경 시에만)
4. 리모컨: 명령 전송 → 호스트 실행 → `result`(성공/실패, 촬영 시 썸네일 포함)
5. 저장: 촬영 폰 갤러리(기존 플로우)

## 4. UX

- **역할 선택 화면**: "이 폰으로 촬영하기"(QR 표시·대기) / "이 폰을 리모컨으로"(QR 스캔)
- **리모컨 화면**: 중앙 프리뷰(호스트 화면비 유지, 레터박스), 가이드 상태 배지(호스트와 동일 문구, 정렬 판정은 '좋아요' 규약 유지), 하단 셔터·타이머 토글·줌 슬라이더·전후면 전환
- **타이머**: 카운트다운을 촬영 폰 화면에 크게 표시(피사체 시점), 리모컨에도 동일 표시
- **촬영 완료**: 리모컨에 썸네일 토스트
- **호스트 화면**: 기존 카메라 화면 + "리모컨 연결됨" 배너·해제 버튼. 로컬 셔터 계속 동작

## 5. 프로토콜

JSON 텍스트 프레임 + JPEG 바이너리 프레임. `hello`/`welcome`에 프로토콜 버전 포함(불일치 시 `reject`로 안내).

| 방향 | 메시지 | 내용 |
|---|---|---|
| 리모컨→호스트 | `hello` | 토큰, 앱 버전, 프로토콜 버전 |
| 호스트→리모컨 | `welcome` / `reject` | 화면비·줌 범위·현재 상태 / 거부 사유 |
| 호스트→리모컨 | (바이너리) | JPEG 프리뷰 프레임 |
| 호스트→리모컨 | `state` | 가이드 요약, 줌, 전/후면, 모드 |
| 리모컨→호스트 | `shutter` `zoom` `switchCamera` `timer` | 명령, `seq` 포함 |
| 호스트→리모컨 | `result` | `seq` 대응 성공/실패 + 썸네일(촬영 시) |
| 양방향 | `ping`/`pong` | 3초 간격 생존 확인 |

## 6. 에러 처리

- 토큰 불일치·중복 접속: `reject` 후 종료 (클라이언트 1대만)
- 끊김(ping 3회 무응답): 리모컨 5초 자동 재접속 → 실패 시 안내 + 재스캔 버튼. 호스트는 "대기 중" 배너로 전환, 촬영 계속 가능
- 접속 timeout: "두 폰이 같은 Wi-Fi에 있는지 확인하세요" 안내(핫스팟 안내 포함)
- 호스트 백그라운드 전환: 세션 종료 통지 후 서버 닫음
- 배압: 소켓 적체 시 오래된 프레임 폐기, 최신 프레임만 전송

## 7. 테스트 전략

- `remote/protocol/`: 엄격 TDD — 직렬화 라운드트립, 페어링 페이로드, 상태 머신 전이, 배압 정책
- `remote/transport/`: 루프백 통합 테스트 — 서버·클라이언트를 같은 프로세스에서 띄워 `hello→welcome→shutter→result` 왕복 검증
- 화면·카메라 연동: 실기기 2대 수동 검증
- 완료 게이트: `tool/verify.sh` 통과

## 8. 범위 밖
